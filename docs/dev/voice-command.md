# 前台语音口令

设置首页「打开后监听语音口令」默认关闭。开启时要求已配置语音模式模型、存在可用的语音识别入口，并由用户授予录音权限。配置缺失时直接引导到语音模式模型或语音转文字设置页。

## 入口与生命周期

`MainActivity` 将冷启动和 `onNewIntent` 的普通 `MAIN` / `LAUNCHER` 请求交给 `VoiceCommandEntry`。分享、通知打开指定会话、最近任务恢复和配置重建不触发。界面恢复前台并获得焦点后才消费请求，普通桌面打开也可能触发。

运行前检查开关、Live 配置及密钥可解析性、每日预算、Live 未运行、录音权限、未锁屏、无通话及无已有录音。此阶段不联网测试 Live，也不启动 Live 前台服务。

触摸、按键、失去前台或焦点、关闭开关、麦克风冲突均取消本次识别；请求编号使迟到的结果失效。已跳过的请求不在麦克风空闲后补录。

## 录音与识别

- 优先使用「语音转文字」当前选中且配置完整的豆包、Fun-ASR、百炼或服务商转写。独立的 `CommandRecorder` 包装 `PcmRecorder`，使用普通 MIC 音源、16kHz 单声道 PCM16，最多采集五秒。正常按住说话仍使用自己的原有实例。
- 没有可用的所选 ASR 配置时回退 `SystemSpeechSession`（`SpeechRecognizer`），仅本入口启用 `singleUtterance`：一句最终结果即结束，空匹配也不循环重开录音，避免将系统识别自己的下一段会话误判为外部占用。正常长按默认仍连续识别；口令会话不修改正常输入的选择或不响应计数。已配置 ASR 的运行错误不再自动切换引擎。
- 五秒到点请求结束采集；系统识别最多再等三秒，流式 ASR 沿用十秒收尾上限，服务商整段转写沿用原有三十秒上限（控制器额外留一秒清理余量）。等待结果不继续采集，触摸、切后台或其他应用用麦克风仍会取消。系统服务的实际采集和释放时序由其实现决定。
- 识别中的文字和最终未匹配文字仅短暂显示在提示条，不落盘；超时、识别失败、空结果、麦克风占用会显示四秒提示。诊断日志只记录阶段、错误类型、文字长度和是否命中，不记录转写正文、音频或密钥。
- 仅收尾结果完整匹配「开启语音模式」（忽略空白和句末常用标点）。中间结果、疑问和否定句、附带其他内容的句子都不触发，也不转交任务模型。

## 麦克风避让与交接

`MicAvailabilityGate` 注册系统录音配置回调并每 100ms 检查录音、音频模式和麦克风静音状态。任何已有录音（包括同应用的其他会话）都会阻止开始；启动后出现其他会话或自身被系统静音即取消，不改音频焦点、通信模式或路由。

自采集通过 `PcmRecorder.audioSessionId` 排除自身。系统识别不公开录音会话 ID：在空闲预检后，只将首次出现的单个 MIC / VOICE_RECOGNITION 会话视为识别服务，其他会话和会话替换均保守中止。这种观察方式无法为同时开录、系统隐藏音源或厂商实现提供绝对零干扰保证。

命中后先取消识别会话和本次协程、释放录音器、撤销观察与定时器，并限时确认系统录音清单已空闲（未命中、取消或麦克风冲突路径直接释放，不等系统空闲轮询），再复查前置条件，打开个人助手页并调用原有 `PersonalLiveRuntime.start()`。语音模式的音频焦点、通信模式、后台服务和暂停恢复策略均保持现状。

## 验证

- JVM：`./gradlew :app:testDebugUnitTest --tests 'com.wangzan101.mika.voice.*'`
- 设备（独立开发包）：`./gradlew :app:connectedDebugAndroidTest -PdevInstall -Pandroid.testInstrumentationRunnerArguments.class=com.wangzan101.mika.ui.VoiceCommandDeviceTest`
- 设备测试只采集短暂本地音频验证录音互斥，不上传音频、不连接 ASR 或 Live；发现已有录音时跳过。
